# Phase 11 — Reports, PDFs & Annual Reports

**Date:** 2026‑10‑06
**Status:** Complete. Awaiting the next instruction (Phase 12 not started).

## Objective
Turn the existing academic, attendance, examination, behaviour, achievement and student data into official school reports: real server‑generated A4 PDFs, an attendance Excel export, and an official annual report with a frozen, publishable final version.

## What inspection found (constraints that shaped the design)
- **No report or PDF infrastructure existed.** Routes always answered JSON, and there were no PDF or Excel dependencies.
- **Weightage** (Phase 4): `exams.weightage_bp` per exam, in basis points of a percent (2000 = 20 %).
  - The total of the year's ACTIVE exams may not exceed 100 %; the exam screen calls exactly 100 % "complete".
  - BR‑EX‑03/04: annual results need exactly 100 %; weightage 0 means "not in the annual result".
  - This was enough for a deterministic annual formula. There is no rule for an annual grade, pass/fail or rank, so none is produced.
- **Results** (Phase 8B): `ResultsService` already returns everything a report card needs:
  - the subject rows (stored derived values, converted marks, grades, pass/fail);
  - completeness and the summary (total, %, result, competition rank);
  - student visibility (submitted subjects only; unlocked = hidden).
- **Mark sheets**: `MarkSheetService.sheet` returns the rows and enforces sheet authorisation.
- **Attendance**: `AttendanceViewService` has the student view (lesson cells with subject and teacher) and the class summary — `countAttendance`, academic calendar. The class cells (with subject, teacher and period) were private; a public read‑only `classRegister` now returns them from the same pass.
- **Branding**: school settings hold name, short name, address, phone, email, motto, website and principal's name (all optional except the names). The official logo master is 8000 px and 2 MB, so a print‑size copy is generated by the existing brand script (resize only).
- **Permissions**: `reports.view` (Admin, Teacher, Student) and `reports.generate` (Admin, Class Teacher) already existed. No new keys are needed.
- **Fonts**: the standard PDF fonts cover Latin text only (D‑101).

## Architecture
- **Request flow:** UI → authorised `/reports/…` route → `ReportService` / `AnnualReportService` → the existing services called with the caller's identity (so their scope applies) → a typed JSON **report document** → the preview (browser) or the PDF/XLSX renderer.
- **Single source:** preview and file are two presentations of the same document. Nothing recalculates marks, grades, ranks, completeness or attendance.
- **PDF** (`modules/reports/render/report-pdf.ts`, PDFKit, server‑side) — A4 portrait, or landscape for mark sheets, with:
  - the official logo and configured school identity only;
  - a running header on later pages;
  - tables that wrap, never split a row and repeat their header on every page;
  - signature lines;
  - "Page x of y" in a footer band that content never enters.
- **Excel** (`render/attendance-xlsx.ts`, ExcelJS): a real Office Open XML workbook.
  - *Lessons* sheet: date, period, admission number, roll, student, class, section, subject, teacher, status, meaning — frozen and filterable header.
  - *Summary* sheet: P/A/L/C/not marked and attendance % per student; empty — not 0 — when there was nothing to measure.
- **Files** go out through `FileResponse`: `attachment` with a sanitised deterministic name, `no-store`, `nosniff`. Nothing is written to disk, logged or audited.
- **File names**, e.g.:
  - `TTLMHSS_2026-27_ExamReport_2026-015_Term-1.pdf`
  - `…_MarkSheet_…`
  - `…_Attendance_<adm>_<from>_<to>.pdf`
  - `…_ClassAttendance_<class>_<from>_<to>.pdf|xlsx`
  - `…_Performance_<adm>.pdf`
  - `…_AnnualReport_<adm>.pdf`

## Reports implemented
| Report | Content | Source |
|---|---|---|
| **Exam report card** | Logo, school, year, exam and dates, student, admission no., class, section, roll; per subject: marks components, max, obtained, converted (if configured), %, grade, pass/fail; total, %, result, rank (scope as configured); signature lines | `ResultsService.myResult` / `studentResultFor`. **Official PDF only for a complete result** (409 otherwise); unlocked subjects become unavailable again |
| **Mark sheet** (landscape) | Exam, class, section, subject, entry teacher, status, maximums per component, pass marks, conversion; per student: roll, admission no., name, component marks (`-` = not entered), total, converted, %, grade, result; "Not final" banner unless submitted | `MarkSheetService.sheet` |
| **Student attendance** | Student details, P/A/L/C/not marked, % (P ÷ (P + A)), every lesson: date, period, subject, teacher, status | `AttendanceViewService.studentAttendance` |
| **Class attendance** (PDF + Excel) | Totals and per‑student counts and %, lessons held; Excel with every lesson cell | `AttendanceViewService.classRegister` (= `classSummary` + cells) |
| **Student performance** | Every visible exam result of the year (subjects, totals, ranks), attendance for the year so far, submitted behaviour, active achievements | Results, attendance, behaviour, achievements services |
| **Annual report** | A student info · B exam‑wise and subject‑wise performance · C attendance · D behaviour (categories, ratings, labels, remarks) · E achievements · F weighting table and annual percentage · G class teacher's remark · signatures | See below |

Empty data reads "Not available", "Not yet assessed", "No records", "Incomplete" or "Not published", never fake zeros.

## Annual report calculation (BR‑AR‑03, D‑102)
`annualPercentBp` in `@ttlmhss/shared` is the single definition:

    annual % = Σ (exam percentage × exam weightage) ÷ 100        (half‑up, 2 decimals)

- **Exam percentage:** the Phase 8B result for the student — Σ final marks ÷ Σ final maximums, using converted marks where configured.
- **Exam weightage:** the Phase 4 configuration of the year's ACTIVE exams.
- **When it is calculated:** only when the weightages total exactly 100 % and every exam with weightage > 0 has a complete result for the student. Otherwise it reads "Not available" and the report lists the reasons ("problems") and cannot be finalized.
- **Unweighted exams** (weightage 0) are shown but never enter the figure.
- **Not produced:** an annual grade, pass/fail or rank — no existing rule defines them.
- **Example (tested):** Term 1 70 % at 40 % and Term 2 80 % at 60 % give **76 %** — not the equal average, 75 %.

## Annual report lifecycle (BR‑AR‑04, D‑103)
| State | Content | Who |
|---|---|---|
| none → **DRAFT** (*Prepare*) | Computed live from current data each time; the student cannot see it; the draft PDF says "DRAFT — not an official report" and shows the system suggestion | Class teacher of the section (that year) or admin |
| DRAFT: *remark* | The final remark (≤ 1000 characters) is required before finalizing. A "start from the suggestion" button copies the suggestion into the editor; the teacher still saves it as their own | Same |
| **FINALIZED** (*Finalize*, confirmed) | No problems allowed; the complete content and the remark are frozen | Same |
| **PUBLISHED** (*Publish*) | The student sees and downloads it (*My reports*) | Admin only |
| *Unpublish* (PUBLISHED → FINALIZED) | Hidden from the student again | Admin only |
| *Reopen* (FINALIZED → DRAFT, reason ≥ 5 characters) | Discards the snapshot; the draft is live again | Admin only (published reports must be unpublished first) |

Every action checks the record's revision.

## Snapshot strategy (BR‑AR‑05, D‑104)
- **Stored:** only annual reports, in `annual_reports` (migration **0013**). Finalization stores the complete display‑ready content as JSON (`snapshot_json`):
  - results with the maximums, grades and labels that applied, and weightages;
  - attendance counts and range, and behaviour with rating labels;
  - achievements with category names, and student/class/exam names;
  - the final remark.
- **Reads:** later views and PDFs use the snapshot only. Tested: changing a mark and renaming an exam afterwards leaves the finalized report at 76 % with the old exam name; after *Reopen* it recomputes (64 %, new name).
- **Not stored:** report cards, mark sheets, attendance and performance reports are generated on request from current data (they are not lifecycle documents).
- **Not built:** a generic document‑versioning system.

## Authorization (permissions.md §16, D‑109)
- **Rule:** every endpoint needs `reports.view` (annual lifecycle and class lists: `reports.generate`) **and** the scope of the service the report comes from. Reports never widen access.
- **Students:** the id always comes from the session. Another student's id (in the query, path or body) → 403, the same as a missing one. Annual reports are visible only once PUBLISHED; otherwise 404 "not published".
- **Class teachers:** their current‑year section — report cards, attendance, performance, annual reports and mark sheets of their section. Another section → 403.
- **Subject teachers:** the mark sheets they are authorised for. Report cards, attendance and annual reports → 403.
- **Administrators:** everything; only they publish, unpublish and reopen annual reports.

## Audit
| Action (entity `annual_report`) | Recorded |
|---|---|
| `annual_report.prepared` | year, student, section |
| `annual_report.remark_changed` | remark before → after |
| `annual_report.finalized` | annual %, weightage total, contributions per exam, attendance counts, final remark |
| `annual_report.published` / `.unpublished` | status before → after |
| `annual_report.reopened` | status, with the reason |

PDF bytes, passwords, tokens and secrets are never logged or audited (tested: no `%PDF` in the audit data).

## Signatures and school identity (D‑107)
- **Signature lines carry role labels only:** Class Teacher; Subject Teacher on mark sheets; Principal / Head of Institution.
- **Principal's name:** printed under the line only when it is configured in School details.
- **School identity:** address, phone, email, website and motto are printed only when configured. No signature images and no invented details.

## UI
- **Reports** (staff menu) — tabs for what the user may produce:
  - Report cards: exam + class → students with Preview and PDF (disabled while incomplete);
  - Mark sheets: the user's sheets;
  - Attendance: class + date range → summary preview, PDF, Excel, a PDF per student;
  - Student performance: Preview and PDF;
  - Annual reports: the class list with status → the annual report page.
- **Annual report page** — status, finalized/published by whom and when, blocking problems, sections A–F, the remark editor and the lifecycle buttons with confirmations, PDF.
- **My reports** (student menu) — published annual reports, exam report cards (complete results only, otherwise "Incomplete · x of y subjects"), an attendance report for a chosen range, and the performance report.
- **Layouts** — responsive: tables scroll inside their own box, filters stack on phones, and the page never scrolls sideways (tested at 820 and 390 px). PDFs stay fixed A4.

## Known limitations / deferred
- **Fonts (D‑101):** standard PDF fonts print Latin text only; characters outside Latin‑1 (e.g. Tamil names) print as "?". An embedded Unicode font (e.g. Noto Sans Tamil) can be added later if needed.
- **Annual grade, result and rank:** not produced, because no existing rule defines them.
- **Bulk generation:** reports are generated one student at a time. There is no bulk "whole class report cards" PDF.
- **Class teacher scope covers the current year only:** past‑year reports are administrator‑only (existing model).
- **Data limits:** attendance reports cover one academic year per request; the performance and annual reports list up to 100 achievements per year.
- **Phase doc location:** this record is at `docs/phases/phase-11.md`, the project's convention (D‑111).

## Decisions requiring approval
- **D‑101:** PDFKit + ExcelJS; Latin‑only standard fonts.
- **D‑102:** annual formula and its preconditions; no annual grade, result or rank.
- **D‑103:** class teachers prepare and finalize; only administrators publish, unpublish and reopen.
